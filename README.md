# 智慧型待辦事項優先排程器

## Proposal Report

### 動機與目標
因為我自己是一個很沒有執行力的人，常常事情很多但我會沒有頭緒要先做哪一個，或是分不清楚哪件事情比較重要需要事先處理的，所以想要做出一個能夠幫我排定優先順序的工具並以此來督促我去完成，每次只顯示一項任務會讓我有最明確的目標可以去執行，希望可以藉此提高我的執行力。

### 預期功能
任務新增與屬性設定：使用者可輸入任務名稱、預估耗時、緊急程度與重要程度。
動態權重計算：系統根據任務屬性與自訂公式，自動計算出每個任務的「優先權分數」。
自動排程與置頂推薦：過濾掉繁雜的清單，系統介面永遠將當下「最高優先權」的任務置頂，引導使用者一次專注完成一件事。
時間逼近自動升級：隨著截止日期逼近，原本低優先級未完成的任務，其分數會隨時間函數自動提升。

### 使用技術
程式語言：C++ 
架構設計：物件導向設計 (OOP)
資料儲存：文字檔或 JSON 檔案輸入輸出 (File I/O)，達成任務資料的持久化。
使用者介面：命令列互動介面 (CLI)。

### 時程規劃
第一週：系統架構設計，定義 `Task` 類別屬性與權重計算的數學公式。
第二週：實作核心資料結構 (Priority Queue / Max-Heap) 以及基本的任務新增、刪除功能。
第三週：實作動態分數更新機制，以及檔案讀取與儲存 (File I/O) 功能。
第四週：邊界測試 (Edge Cases Test)、除錯 (Debugging)，並整理程式碼。
第五週：撰寫專案 README 文件，並發布 GitHub Release。

### 與課程的關聯
資料結構的應用：此次專題的核心是 優先權佇列 與 最大堆積。若使用一般陣列尋找最高優先級任務需耗費 O(n) 的時間，但透過自行實作 Max-Heap，能將新增任務與取出最高優先級任務的時間複雜度完美降至 O(log n)，實際應用了課程中探討的樹狀結構與效能優化概念。
進階程式設計：深度運用 物件導向 (OOP) 的封裝特性來管理任務，並會實作 運算子多載，讓程式知道如何依據自訂的演算法公式來比較兩個任務物件的優先大小。同時也會涵蓋指標操作與檔案處理的技術。

## Prototype Report

### 目前進度
核心資料模型 (Task 類別)：Task 類別封裝，包含 ID 自動生成、權重公式計算以及運算子多載，使其能直接放入堆積進行比較。
高效排程引擎 (MaxHeap)：實作了泛型最大堆積
雙重索引系統 (DateBST)：除了優先權，額外實作了二元搜尋樹（BST），支援以「截止日期」為鍵值的區間搜尋。
動態更新機制 (Multithreading)：利用背景執行緒 (std::thread) 與條件變數 (std::condition_variable)，達成每 30 秒自動重新計算任務分數並重建堆積的功能

### 與課程的關聯
物件封裝 (Encapsulation)： 定義 Task 類別（屬性如優先級、截止日期、權重）在資料結構中稱為「節點 (Node)」或「元素 (Element)」。
最大堆積 (Max-Heap)： 實作了 siftUp（向上篩選）與 siftDown（向下篩選），確保每次 insert (新增) 或 extractMax (取出最優先任務) 時，最高分的任務永遠在陣列的第 0 格，時間複雜度維持在 O(log n)。
Binary Search Tree, BST (二元搜尋樹)：程式碼中的 BST 類別，用來作為「依日期查詢」的輔助索引。因為 Heap 只能保證「最大值在哪」，無法快速搜尋「特定日期的任務」。因此這份程式碼多建了一棵 BST，以 YYYYMMDD 字串作為 Key，達成 O(log n) 的日期搜尋與 O(n) 的依日期中序走訪 (inorderAll)。
動態分數更新 (Decrease/Increase Key)： 當任務的權重改變時，像是快過期了，它在 Heap 中的位置必須重新調整（Sift-up 或 Sift-down）。對資料結構內部的重新平衡 (Rebalancing)。

## Final Report

### 專案說明
智慧任務排程器是一個具備高度自訂性的動態排程系統。跟一般傳統的排程器不同的地方在於捨棄了靜態的待辦清單，改用數學模型與指數衰減函數來計算任務權重，並交由 Max-Heap 與 BST 來優化資料的存取效能。使用者可以自行設定各變數的權重。可以像調整模型超參數一樣，自由修改緊急度、重要度的佔比，或是透過調整底數與衰減速率，來改變時間逼近時的分數加成幅度。系統能根據這些動態參數即時重算所有任務的分數，並重新建構底層的資料結構。

### 使用方式
下載html檔之後直接執行，可以在任務名稱下的輸入欄輸入要新增的任務的名稱，在下面可以選擇此任務預計花費的時間、緊急程度和重要程度，截止日期則可填可不填以增加彈性。也可以透過截止日期查詢特定的任務。在最下面可以調整公式中各項變數的權重。透過智慧排程器，使用者便可知道目前對他而言最該先做的事是什麼。

### 至少提出系統內一個功能流程是使用不同資料結構或演算法來進行實際效能分析跟比較
1.在下方日曆輸入框選擇特定日期，系統會遍歷二元搜尋樹，以O(logn)的效能快速調閱該日期的所有待辦事項，或透過中序走訪（Inorder Traversal）依序列出所有帶有期限的任務。如果是遍歷的話則時間複雜度會是O(logn)
2.在處理不斷動態新增、完成任務的排程器時，若每次操作都將整個陣列重新排序，時間複雜度會高達O(nlogn)。採用以陣列實作的完全二元樹（Max-Heap），能將插入與取出最大值的成本穩定壓在 O(logn)
3.當公式面板的參數被修改時，所有任務的分數都會改變。此時若使用單純的氣泡排序或插入排序，在龐大資料量下效能會極速惡化（O(n^2)）。在專案中我使用了heapRebuild()（即 Heapify 操作），能將重組最大堆積的複雜度控制在理想範圍。

### 演算法分析
演算法主要分三部分：
1.動態優先權計分演算法：這部分負責決定每個任務的絕對優先級，結合了線性加權與非線性（指數）衰減。
1.1基礎分數 (Base Score)： 公式將預估時間T放在分母並取對數，意味著「耗時極長」的任務分數會被平滑地壓低，避免長任務霸佔佇列；而加 是為了避免log_2(1)=0導致的除以零錯誤。
1.2指數衰減因子 (Exponential Decay Factor)： 公式是一個典型的自然底數衰減模型，距離截止日期的天數（days）越小，公式的值會越逼近 1，使得整體分數呈現非線性的急速爬升。
1.3時間複雜度： O(1)。無論有多少任務，單次計算分數的成本都是常數時間。
2.最大堆積排程演算法 (Max-Heap Operations)：程式碼捨棄了每次重算後使用O(nlogn)的全陣列排序，而是利用陣列來實作完全二元樹(Complete Binary Tree)，是優先權佇列（Priority Queue）底層演算法。
2.1插入與向上維護 (heapInsert & heapUp)：新任務會先被push到陣列最尾端，接著透過Math.floor((i-1)/2)找到父節點進行比較。如果子節點分數大於父節點，就執行交換。最壞情況下只需交換至樹根，複雜度為樹的高度O(logn)。
2.2提取與向下維護 (heapExtractMax & heapDown)：
取出陣列索引0的最大值後，將陣列最後一個元素移到頂部，接著透過2i+1與2i+2找出左右子節點，與兩者中較大的那一個交換並持續下沉。複雜度同樣是O(logn)。
2.3我的專案的重建邏輯是清空陣列後，用forEach重新執行heapInsert。連續插入n個節點的時間複雜度為O(nlogn)。
3. 二元搜尋樹檢索演算法 (BST Retrieval & Traversal)：為了補足Heap無法快速依照「日期」進行條件搜尋的缺點，程式碼利用截止日期作為鍵值（Key），額外維護了一棵二元搜尋樹。
3.1遞迴搜尋 (_srch)：輸入日期後，演算法會從根節點開始比對，小於往左走、大於往右走。在理想狀態（樹狀平衡）下，每次比對都能排除一半的資料，搜尋複雜度為O(logn)。
3.2中序走訪 (inorder & _io)：當使用者點擊「全部(依日期)」時，演算法嚴格執行「左子樹、父節點、右子樹」的遞迴遍歷。這保證了輸出的任務陣列會自然依照日期由小到大排列，時間複雜度為 O(n)。
3.3我的專案使用的是最基礎的BST，並沒有自我平衡機制。如果使用者「依序」新增了截止日期為 5/1, 5/2, 5/3, 5/4的任務，這棵樹會一直往右長，最終退化成一條類似Linked List的偏斜樹 。此時，搜尋的複雜度就會從 O(logn)崩跌至O(n)。
