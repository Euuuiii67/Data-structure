# 智慧型待辦事項優先排程器

## Proposal Report

### 動機與目標
因為我自己是一個很沒有執行力的人，常常事情很多但我會沒有頭緒要先做哪一個，或是分不清楚哪件事情比較重要需要事先處理的，所以想要做出一個能夠幫我排定優先順序的工具並以此來督促我去完成，每次只顯示一項任務會讓我有最明確的目標可以去執行，希望可以藉此提高我的執行力。

### 預期功能
任務新增與屬性設定：使用者可輸入任務名稱、預估耗時、緊急程度與重要程度。
動態權重計算：系統根據任務屬性與自訂公式，自動計算出每個任務的「優先權分數」。
自動排程與置頂推薦：過濾掉繁雜的清單，系統介面永遠將當下「最高優先權」的任務置頂，引導使用者一次專注完成一件事。
時間逼近自動升級：隨著截止日期逼近，原本低優先級未完成的任務，其分數會隨時間函數自動提升。

### 使用技術
程式語言：C++ 
架構設計：物件導向設計 (OOP)
資料儲存：文字檔或 JSON 檔案輸入輸出 (File I/O)，達成任務資料的持久化。
使用者介面：命令列互動介面 (CLI)。

### 時程規劃
第一週：系統架構設計，定義 `Task` 類別屬性與權重計算的數學公式。
第二週：實作核心資料結構 (Priority Queue / Max-Heap) 以及基本的任務新增、刪除功能。
第三週：實作動態分數更新機制，以及檔案讀取與儲存 (File I/O) 功能。
第四週：邊界測試 (Edge Cases Test)、除錯 (Debugging)，並整理程式碼。
第五週：撰寫專案 README 文件，並發布 GitHub Release。

### 與課程的關聯
資料結構的應用：此次專題的核心是 優先權佇列 與 最大堆積。若使用一般陣列尋找最高優先級任務需耗費 O(n) 的時間，但透過自行實作 Max-Heap，能將新增任務與取出最高優先級任務的時間複雜度完美降至 O(log n)，實際應用了課程中探討的樹狀結構與效能優化概念。
進階程式設計：深度運用 物件導向 (OOP) 的封裝特性來管理任務，並會實作 運算子多載，讓程式知道如何依據自訂的演算法公式來比較兩個任務物件的優先大小。同時也會涵蓋指標操作與檔案處理的技術。

## Prototype Report

### 目前進度
核心資料模型 (Task 類別)：Task 類別封裝，包含 ID 自動生成、權重公式計算以及運算子多載，使其能直接放入堆積進行比較。
高效排程引擎 (MaxHeap)：實作了泛型最大堆積
雙重索引系統 (DateBST)：除了優先權，額外實作了二元搜尋樹（BST），支援以「截止日期」為鍵值的區間搜尋。
動態更新機制 (Multithreading)：利用背景執行緒 (std::thread) 與條件變數 (std::condition_variable)，達成每 30 秒自動重新計算任務分數並重建堆積的功能

### 與課程的關聯
物件封裝 (Encapsulation)： 定義 Task 類別（屬性如優先級、截止日期、權重）在資料結構中稱為「節點 (Node)」或「元素 (Element)」。
最大堆積 (Max-Heap)： 實作了 siftUp（向上篩選）與 siftDown（向下篩選），確保每次 insert (新增) 或 extractMax (取出最優先任務) 時，最高分的任務永遠在陣列的第 0 格，時間複雜度維持在 O(log n)。
Binary Search Tree, BST (二元搜尋樹)：程式碼中的 BST 類別，用來作為「依日期查詢」的輔助索引。因為 Heap 只能保證「最大值在哪」，無法快速搜尋「特定日期的任務」。因此這份程式碼多建了一棵 BST，以 YYYYMMDD 字串作為 Key，達成 O(log n) 的日期搜尋與 O(n) 的依日期中序走訪 (inorderAll)。
動態分數更新 (Decrease/Increase Key)： 當任務的權重改變時，像是快過期了，它在 Heap 中的位置必須重新調整（Sift-up 或 Sift-down）。對資料結構內部的重新平衡 (Rebalancing)。

## Final Report

### 專案說明
智慧任務排程器 (Priority Scheduler) 是一個動態任務管理工具，不像傳統的待辦清單（To-Do List）僅依賴使用者手動排序，我的專案使用了數學權重演算法，並將底層資料儲存交由最大堆積（Max-Heap）與二元搜尋樹（BST）來管理。系統會根據任務的「緊急程度」、「重要程度」、「預估時間」以及「距離截止日期的天數（時間衰減係數）」，動態計算出一個優先權分數。隨著時間推移，逼近或超過截止日期的任務分數會呈指數型增長，系統會利用最大堆積的特性，自動將最迫切需要處理的任務推至頂端，協助使用者保持專注。
